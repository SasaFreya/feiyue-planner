# 开源接入实现与验收

日期：2026-10-16。用户明确要求实际接入此前的开源候选。本轮已实现下列四个可操作入口，默认放在功能库的“开源扩展”，可自行设为常用。仍只更新源码与开发预览，不打包。

## 使用方式

### 重复安排

- 功能库 → 重复安排。填写标题、项目、开始日期、日/周/月频率、间隔、次数与预计分钟，先查看日期预览，再确认加入日历。
- 次数 1–100，间隔 1–12；使用浮动 UTC 表达日历日期，避免本机时区改变导致日期偏移。每月 29–31 日按 rrule 规则跳过没有该日期的月份，界面有说明。
- 每个实例有独立稳定 ID 和 repeatSeriesId，可分别勾选、排序、计时及在日历调整。普通事项编辑保留系列标识，并说明只改这一次。生成安排不会创建虚假的实际工时。
- 一次生成通过现有 workspace 命令和 SQLite 事务写入。没有为重复功能新增第二份任务库。还没有整系列规则编辑/自动续建/整系列删除入口。

### Super Productivity 导入

- 在来源应用导出未加密完整 JSON，功能库 → Super Productivity → 选择本机备份。兼容根级 task/project 切片以及 CompleteBackup.data 包装。
- 文件大小上限 10MB。预览新项目、任务、跳过与重复数量，确认前不写入。采用命名空间稳定 ID；已导入 ID 跳过，避免重复导入或覆盖本地修改。
- `timeEstimate` 按官方定义从毫秒转成飞跃的预计分钟。`dueWithTime` 优先于 `dueDay`，按北京时间取安排日；有 `doneOn` 时保存完成日。保留完成状态。子任务以独立事项导入。
- 不导入附件、提醒、归档历史或重复规则；指定时刻当前只转成当天安排。项目使用飞跃的默认春日颜色，不完整迁移来源主题。
- `timeSpentOnDay` 是按日累计，缺少真实起止时间：只预览累计，不虚构 sessions、不把累计工时画成实际日历片段。
- 这是单向文件数据互通，不是 Super Productivity 的全功能移植或实时同步。

### solidtime 本机只读连接

- 功能库 → solidtime 工时。填写本机服务端口、组织 UUID、API Token 和查看日期，主动连接。
- 根据官方规范调用 `GET /api/v1/organization/{organization}/projects` 和 `GET /api/v1/organization/{organization}/time-entries`，仅连接 127.0.0.1 本机服务；不支持云服务地址、远程实例、反向代理自定义路径或自签证书。
- 返回最多 500 条记录，再按所选北京时间当天交集统计；达到返回上限时明确提示结果可能不完整。组织范围可能包含其他成员，这一点在界面说明。正在进行的记录使用读取时刻计算，不自动后台刷新。
- Token 用于当前请求，不写入共享状态、SQLite、日志或备份；页面退出/断开清除，断开会中止界面请求。仅在请求处理的临时内存中使用，不写来源服务。
- 来源工时与飞跃实际计时分开展示，不自动导入 sessions，不重复累计。

### ActivityWatch 本机活动回顾

- 先运行自己的 ActivityWatch 服务及窗口 watcher，再到功能库 → 电脑活动回顾，主动连接端口（默认 5600），选择窗口来源和日期。
- 通过官方 SDK 获取 `currentwindow` 类型来源及事件；单次最多 5000 条，达到上限时提示汇总不完整。应用活动按当日交集和不重叠片段汇总，避免同一来源的重叠重复累计。
- 接口只将应用名和时段汇总传给飞跃界面，剔除窗口标题、网址；读取的活动留在页面内存，不写飞跃 SQLite。不自动连接、轮询、安装/启动采集或修改 ActivityWatch。
- 这不是项目专注工时，未扣除 AFK，不自动叠加手动计时。目前不支持开启 API Key 的 ActivityWatch 服务，也不混合多台设备、浏览器 watcher 或多个来源的时间。

## 实现位置与接口保护

- `features/integrations/recurrence.ts`：rrule 日期计算；`super-productivity.ts`：备份格式转换和去重；`activity-model.ts`：活动切片、聚合和隐私字段剔除。
- `features/integrations/pages.tsx`：四个精简入口；`feature-registry.ts`：功能库登记；`daily-plan/workbench.tsx`：按需加载和显示。
- `desktop-shell/integrations.ts`：固定本机地址、固定官方读取路径、超时、格式/端口验证、来源与 X-Feiyue-Request 校验。solidtime 请求拒绝重定向，错误消息不回显凭据或上游响应正文。
- `desktop-shell/server.ts` 用于下次新版桌面服务；`vite.config.ts` 同时为开发预览提供连接接口，因此不用重新打包就可以试用。原安装版仍提供现有状态服务，不要求中断它或更改正式数据路径。
- `public/open-source-integrations-NOTICES.txt` 保留本轮新依赖的完整许可文本。aw-client 0.4.1 包内 LICENSE 为 MIT，但 package.json 元数据声明 MPL-2.0，两者均按实际材料记录；本轮未改动上游源码。来源协议适配代码为本项目独立实现，未复制 solidtime 的 AGPL 源码。

## 验证结果

- TypeScript 检查通过；20 项自动测试全部通过（原 15 项 + 新增 5 项集成测试）；界面生产构建通过，输出到临时目录，不生成安装包。
- 测试覆盖月末重复跳月、次数上限、实例独立与日历关联；来源时间单位、指定时刻优先、导入去重和不生成假历史；活动裁剪去重和剔除标题；真实 SDK 对模拟协议读取；solidtime bearer token、跨午夜交集和只读请求；原迁移、并发、计时与显示偏好回归。
- 临时库浏览器实际操作：生成 3 次每周课程并确认进入 10 月 16/23/30 日月历；读取并确认导入测试备份的 1 项目/1 任务；连接模拟 ActivityWatch 并显示 45 分钟活动；连接模拟 solidtime 显示 1 小时记录；断开后 Token 字段清空。
- 最终只读核对临时库：4 个任务、2 个项目、3 个重复实例、1 个导入任务、0 个实际计时片段，模拟 Token 未写入。未往用户真实库添加验收事项。
- **未验证**：真实用户 Super Productivity 备份文件、真实 solidtime/ActivityWatch 服务、原生 Mac 新界面操作与新包升级。模拟测试通过不代表这些真实外部应用已经安装、运行或完成授权。
