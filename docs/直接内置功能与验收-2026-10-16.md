# 飞跃直接内置能力（0.3.0）

用户纠正：不是导入/连接外部服务的入口，而是在飞跃里面直接可用，不要套娃。此前“接入完成”的表述过度，连接器不能等同于内置完整应用。

## 本轮实际实现

- **专注执行**：原 Super Productivity 入口改为飞跃自有专注页面，选择既有未完成事项，正计时或指定分钟倒计时，暂停/完成写入原 sessions，清单、日历、时间记录同源。倒计时由已有心跳精确截断。再次开始为新段/新目标；没有休息轮次、完整上游番茄钟或自动循环。旧备份导入折叠为可选工具。
- **项目工时**：取消 solidtime 连接表单的产品入口，合并到现有“时间记录”按项目/事项统计，日/周/月/年/自定义、修正与 CSV 导出使用已有本机数据。旧 solidtime 查询地址映射为时间记录，不新增重复页面。不是安装了 solidtime 完整服务。
- **电脑活动回顾**：飞跃随包携带约 60KB 的 macOS Swift 采样组件；通过 NSWorkspace 只取前台应用名称、通过 IOHIDSystem 获取闲置秒数。每 5 秒采样，同应用连续时段合并；闲置达到 60 秒、采样间隔超过 15 秒或睡眠间隔跳过。应用切换边界有约 5 秒采样误差。无屏幕录制、辅助功能请求，不读取窗口标题/网址/截图/键盘内容。
- 活动默认关闭，在飞跃页面点击开启，设置保存后随飞跃启动，退出停止；只在 macOS 桌面打包环境可开启。活动写入 FeiyuePlanner/computer-activity.sqlite（独立 SQLite/WAL），不混入手动工时。当前仅按日期显示应用汇总；不是 ActivityWatch 上游服务二进制内置。官方完整包下载缓慢且失败，未把它假称为已经安装。
- 外部 solidtime 与 ActivityWatch 的旧适配代码保留供未来兼容，但默认功能流程不依赖端口、Token 或外部应用。组件说明已区分参考交互、自研能力和真实库调用。rrule/FullCalendar/dnd-kit 等原有库继续使用。

## 验证与安装

- 23 项自动测试通过：包括原数据模型、来源连接器、闲置/睡眠/逆序样本排除、内置接口默认关闭、跨站请求拒绝和数据隔离。TypeScript 与桌面构建通过。
- 真实 Swift 组件在临时目录运行验证：返回 available/running；实际读到应用名称并积累约 5 秒真实活动，暂停后 running=false，历史记录保留。最初 CGEventSource 单独读取的闲置值异常，改用 IOHIDSystem 后复验成功。没有把临时样本写进用户活动库。
- 已将 0.3.0 打包替换原 desktop/飞跃日程规划本.app，同一路径；原生窗口验证专注页与电脑活动开关可用，正式活动采集保持默认关闭。时间记录沿用既有经过验证的页面，本次没有向真实任务添加测试工时。
- 更新前备份：installation-backups/2026-10-16-native/（SQLite 在线备份、完整状态 JSON、旧业务 asar）。启动后只读对比 workspace、entries、sessions、plans、links、orders 全部一致，24 个任务、11 段计时；不覆盖用户在验证期间自行调整的偏好。旧应用完整副本清理，保留小体积业务包和数据备份。

## 尚未实现/验证

- 没有移植三个项目的完整代码库和全部功能，不应描述为“安装了完整 Super Productivity/solidtime/ActivityWatch”。当前满足个人任务专注、本机项目工时和应用活动记录这三个核心用途。
- 活动库目前不包含在“导出完整备份”的原规划 state JSON 内；保管时还应复制独立 computer-activity.sqlite（运行中用 SQLite 在线备份，退出后复制）。活动库专用导出/清理/恢复 UI 尚未做。
- 尚未验证长期续航、系统锁屏的每种情形、不同 macOS 版本；目前支持本机 Apple Silicon macOS 13+。未来补 AFK 更精细处理、专注休息轮次以及应用时段手动归入项目，不把这些写为已交付。
