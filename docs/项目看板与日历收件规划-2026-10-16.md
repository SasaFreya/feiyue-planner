# 项目管理看板、栏目排序与日历收件

## 用户要求与本轮交付

用户要求把“容量与分配”改为“项目管理”；界面参考原日历的精致程度，采用看板；侧栏栏目允许自己拖拽排序；文件直接拖入日历生成安排，可选默认保存位置；支持粘贴微信聊天，正确判断责任归属。聊天案例仅是分析材料，用户是刘静雯，不授权把案例写成个人任务。

**源码和本机预览已实现，本轮未打包或替换桌面版。**

### 项目管理

- 原 capacity 功能 ID 保留，名称与描述改为项目管理，沿用已有常用开关和偏好。
- 独立轻量看板替换旧容量表单：每项目一列，纯色圆点、细进度线、任务数量和小任务卡，卡内显示安排日期与预计分钟；起止日期默认折叠，不再在每列顶端放两个大输入框。
- 支持搜索、显示已完成、逐项目新建、编辑和勾选；拖拽事项换项目，不改变原日期与计时历史。项目设置保留在原分类页，不另建数据。
- 自动安排改为预览再确认；按原 distribute 规则仅分配有截止日期项目的未安排事项，保留已有安排，超容量仍可能排入。没有把预计工时当实际工时。横向滚动查看多项目，未设截止时明确显示未设，不编造剩余天数。

### 侧栏排序

- 用已有 dnd-kit 的 SortableContext 实现鼠标/触摸拖拽；悬停出现小把手。
- 支持键盘聚焦把手，空格拿起、方向键移动、空格放下。
- pinnedFeatures 读取改为尊重保存顺序、去重并忽略未知 ID；存储仍走原 settings 通道，多窗口共用。功能库为固定入口，不参与拖拽，避免找不到收纳页。

### 日历收件

- 新增“导入文件 / 聊天”入口，支持原生文件拖放、文本拖放，以及非输入框位置粘贴文字。
- 拖到带 data-date 的日历日期格，会把那天作为用户明确选择的日期；从按钮/普通粘贴进入不会把消息发送日期当计划日期。
- 先本机规则识别，展示候选标题、归属、日期、原文依据；所有候选默认不勾选。可改标题、日期、项目，手动补条目。无日期确认后进待安排，绝不偷偷填今天。
- 文本型文件（txt/md/csv/json/ics，单个不超过 100KB）读为文本参与规则识别；不等于理解任意表格或完整 ICS 规则。二进制文件如 PDF、图片、Word 仅保存原件，可用文件名做手动候选，尚无 OCR/文档语义抽取。
- 文件限制：最多 5 个、单文件 8MB、总计 12MB；正文最多 100000 字符。确认后复制到默认路径下“飞跃收件/随机目录”，保存来源.txt，不覆盖原件。保留 SHA-256；操作不会执行或打开文件中的指令。
- 原件归档成功后用原 workspace 命令创建任务，用 entries 的 import:任务ID 记录来源路径/依据，在任务编辑页可查看；不另建一套日历数据。若规划保存失败仍由统一待保存队列提示，原件可能已归档，不能说两者是一个原子事务。

### 保存位置与身份

- 设置新增“文件与聊天识别”，默认展示刘静雯为本次识别姓名，允许修改并保存。
- 默认附件位置 FeiyuePlanner/Attachments；预览可填写已有目录绝对路径并保存，桌面源码已接 Electron 原生目录选择对话框，需后续用户要求打包后才能在桌面版使用该新对话框。
- 改位置只影响未来导入，旧文件路径保留不迁移；同名文件使用独立随机目录、绝不覆盖。
- 原文件不包含在现有日程 JSON 完整备份内（只含来源路径），界面已注明要同时保管文件夹；打包完整附件备份/恢复尚未做。

## 聊天案例的判断

- 14:47 系统试用及建议：原文 @刘静雯，标记“提到你”，是否承担需要确认；未给出明确安排日期，留空。
- 15:58 写 YB 先公开征询，不能据此指派刘静雯；16:13 明确交给欣欣和钦钦，后续指派覆盖前面的征询，候选标“他人的事”、列出指派对象。
- 15:59 指导邀请和 16:11 赞许是上下文，不各生成个人待办。
- 2026-10-13 各消息的时间只用于上下文；不会自动排到那一天或那些钟点。相对“明天”按消息日期推导，仍需用户确认。
- 当前规则识别有局限：昵称/别名、多人转述、撤回和更复杂的主题切换不能保证理解。最后的“请某某来写”仅关联最近的写作候选；模糊结果必须人工核对，不宣称大模型已经理解任意聊天。
